## 1. プロジェクトの目的

- **Slay the Spire 2 にインスパイアされたオリジナルのデッキ構築型ローグライクゲーム**を作る（2026-10-03 再定義）。
  - ~~デッキ構築型ローグライク向けの汎用デッキトラッカー＆ビルド管理アプリ~~（変更: 2026-10-03。オーナーより「プレイ記録・分析用のトラッカーは定義の間違い」）
- カード・キャラクター（エージェント）・敵はデータ定義を追加するだけで増やせる拡張性を重視。
- 進め方: まず戦闘 1 回を遊べるようにし、キャラクター固有の特性は決めずに無個性な初期デッキから始める。
- 将来構想: エリート・休憩所・ショップ・イベント・宝箱の中身、キャラクター固有カード、PHP/Laravel + AWS バックエンド連携（セーブ・ランキング等）、AI シナジー分析。
- **現在のフェーズ: フロントエンド（ローカルで遊べるプロトタイプ）に集中。** バックエンド連携やデータ永続化はまだ行わない。

### 参考にしているスレスパの戦闘仕様（2026-10-03 調査）

- 毎ターン開始時: エナジーを最大値（3）に戻し、5 枚ドロー。プレイヤーのブロックは 0 に戻る。
- カードはコスト分のエナジーを払って使い、使ったカードは捨て札へ。ターン終了時に手札は全て捨て札へ、余ったエナジーは失われる。
- 山札が尽きたら捨て札をシャッフルして山札にする。
- ブロックは攻撃ダメージを 1:1 で防ぐ。敵のブロックは敵自身のターン開始時に消える。
- 敵は次の行動をインテント（攻撃: 剣アイコン＋ダメージ、`6x3` は多段攻撃、防御: 盾アイコン、バフ・デバフ）で予告する。
- 基本カード: ストライク（1 コスト・6 ダメージ）、防御（1 コスト・ブロック 5）。スレスパ 2 の初期デッキは各 4〜5 枚＋キャラ固有カード。
- 未実装の主な要素: 敏捷、脱力（与ダメージ -25%）、弱体（被ダメージ +50%）、複数の敵。
- 実装済みの拡張効果（2026-10-03）: 多段攻撃、自己 HP 損失、筋力（戦闘中 / このターン）、ターン終了ブロック、廃棄、使用時コピー追加。
- 参考: [Combat Mechanics (StS2 Wiki)](https://slaythespire-2.com/guides/combat-mechanics-guide)、[Mechanics (StS1 wiki.gg)](https://slaythespire.wiki.gg/wiki/Mechanics)

## 2. 開発背景・ストーリー（Why）（2026-10-03 共有）

- オーナー自身がデッキ構築型ローグライクの大ファン（特に Slay the Spire 2）。

### 開発スタイル

- 週末を使った個人開発。
- まず Expo のローカル UI/UX プロトタイプで小さく検証し、段階的に拡張する長期ロードマップ。
- Cursor + Claude をパートナーとして活用。型安全（TypeScript Strict）・保守性の高い設計・TDD を重視。

### 提案・設計の判断基準

- **プレイヤー体験を最優先する。** 機能や設計を提案するときは「プレイ中・プレイ後のプレイヤーにとって嬉しいか」を最初の判断軸にする。
  - 例: スマホの片手操作でカードを出しやすいこと、敵のインテントと自分の状態がひと目で分かること、1 戦の手応え。
- 週末開発なので、1 回の作業で完結して動くものが確認できる小さな単位で進める。

## 3. エンジニア戦略・技術ロードマップ（2026-10-03 共有）

### エンジニアリング上の目的

- 趣味の個人開発を通じて、React Native/Expo・TypeScript・PHP/Laravel・AWS の実践的なスキルアップを図る。
- AI 連携開発（Cursor + Claude）で、安全で再現性の高い「プロトタイピング → プロダクション運用」のパターンを確立する。

### フェーズ別ロードマップ

| フェーズ | 内容 | 状態 |
| --- | --- | --- |
| Phase 1: フロントエンド | Expo (SDK 57) + TypeScript。ドメインモデル（Card, Deck, Relic, RunLog 等）の型定義と UI からの分離。ローカルステート + Custom Hooks で状態管理 | **進行中** |
| Phase 2: バックエンド | PHP (Laravel REST API)、Clean Architecture、TDD | 未着手 |
| Phase 3: インフラ | AWS: CloudFront + S3（カード・レリック画像配信）、App Runner / ECS Fargate（コンテナ API）、RDS（PostgreSQL または MySQL）、Secrets Manager（機密情報） | 未着手 |
| 将来 | AI によるデッキシナジー解析 | 構想 |

### Phase 1 の設計方針（フロントエンド）

- ドメインモデルは UI から独立したモジュール（例: `src/domain/`）に置き、Phase 2 の Laravel API のリソースと 1 対 1 で対応付けられる形にする。
- ロジック（枚数加算、統計計算など）は純粋関数として切り出し、テストしやすくする。
- 状態管理は Custom Hooks（例: `useDeck`, `useRelics`）に閉じ込め、後でローカル保存や API 呼び出しに差し替えられるようにする。

### 品質担保ルール（AI 活用開発）

- TDD の考え方をベースにする。ロジック変更時は型チェック（`npx tsc --noEmit`）を徹底する。
- ~~パッケージ追加やコマンド実行はエンジニアの承認を得てから行う~~（変更: 2026-10-03。毎回の承認は手間が大きいため）
- **コマンドは基本自動。取り消せない・外部に影響する操作だけ承認制**（2026-10-03 決定）。
  - 要承認: パッケージの追加・削除、一括削除やプロジェクト外の操作、`git push` / `reset --hard` / `--force`、`sudo`、デプロイ・外部サービス操作。
  - 安全網として、区切りごとにローカルコミットを作る（コミットは承認不要）。
  - 詳細は `AGENTS.md` の行動ルールを正とする。
- コード生成では「保守性・再利用性・拡張性」を最優先し、コンポーネント分割でスパゲッティコード化を防ぐ。

### 戦闘エフェクト（2026-10-03）

- 追加パッケージなし。React Native 標準の `Animated` のみ使用（`react-native-reanimated` は未導入）。
- 仕組み: ロジックが `CombatState.events`（直前の操作 1 回分の `hit` / `blockGain` / `defeated`）を書き出し、UI がそれを読んで演出する。reducer が操作のたびに `clearEvents` で前回分を捨てる。
- 1 回の操作で複数イベントがあると `MOTION.eventStagger`（280ms）ずつずらして再生する（敵の多段攻撃が 1 発ずつ見える）。
- 演出の内容:

### カードのシナジー（デッキ構築の軸）（2026-10-04、オーナーの要望）

- **方針**: 「強いカードを使うだけ」から「組み合わせで強くなる」ゲームへ。単体では控えめで、軸がそろうと爆発するカードを足した。

### デバフ無効は回数制のアーティファクトに統一（2026-10-07、オーナーの要望）

- **要望**: デバフを無効にする敵が「同じデバフは一度しか受け付けない」のをやめ、受け付けない回数（N 回）にしてほしい。N はこちらで決めてよい。
- **仕組み**（`EnemyTrait` の `artifact{charges}`、戦闘中の残りは `EnemyState.artifact`）: デバフの付与・延長・倍化を 1 回ずつ無効にし、1 回ごとに残りが 1 減る。0 になると、同じ種類のデバフもターン数が加算される。1 枚のカードが弱体と衰弱を両方かけると 2 回分消費する。画面の数値は残り回数で、0 になるとアイコンが消える。ログは「アーティファクトがデバフを防いだ（残り n）」。章の強さの倍率では回数は増えない。
- **旧・加護**はもともと回数制だったので、名前をアーティファクトに揃えた。氷の魔女 2、凍れる女王 3、ラスボス 2 はそのまま。
- **旧・不屈の敵**の回数: 通常（岩の兵士・沈都の衛兵・歯車の兵）は 1。安いデバフを 1 回当てればはがれ、そのあと本命を重ねられる。玄武岩の巨像は眠りで長く戦うので 2。歯車の機皇はボスなので 3。
- カード名「大樹の加護」や敵の行動「風の加護」は性質とは別なので変えていない。

### 宿り木の予定ダメージを HP ゲージで見せる（2026-10-07、オーナーの要望）

- ターンを終えると、敵のブロックが消えたあと・行動する前に、宿り木の数値と同じダメージが入る。その分を、戦闘中の敵の HP ゲージの右側だけ緑（`COLORS.heal`）にする。残りが全部緑のときはゲージを緑の輪で囲み、このままターンを終えると倒せる、と分かるようにする。

### 途中であきらめてタイトルへ（2026-10-07、オーナーの要望「どこからでもゲームを中断してメニューに戻れる」）

- セーブはまだ無い。戻るとそのランは消え、次に始めるときは新しいランになる（`GameRoot` が `RunRoot` を外すと `useRun` の状態も捨てる）。

### 全体の音量を 2 倍（2026-10-07、オーナーの要望「効果音と BGM のバランスはそのまま」）

- `OUTPUT_GAIN = 2`（`src/audio/gain.ts`）。効果音は `volume × 0.51 × 2`、BGM は曲ごとの `volume × 2`。比率用の数値は変えていない。
- 再生機の音量は 0〜1。大ダメージの効果音だけ 1.02 になるので 1 で止まる（他は 2 倍のまま 1 未満）。1 を超える値をそのまま渡すとブラウザでは例外になる。

### 手札が透けて見える（2026-10-07、プレイして気になった点）

- 手札が 10 枚近くまで重なると、手札全体が透明に見えることがあった。条件は「多いとき」としか分からなかった。
- 原因は次の通り。
  - 使えないカードはカード全体の不透明度を 0.4 にしていた。重なると、うしろのカードと背景が透けて、手札が幽霊のように見える。カード自体は不透明のまま、上に暗い覆い（`COLORS.cardDim`）を載せるように変えた。
  - カードをつまむと元の位置を 0.25 の透明度で残していた。一番手前のカードが手札のほとんどを覆っているので、そこが透けると手札全体が透明に見える。つまんでいる間は元の位置を消し、指についてくるカードだけを描く。
  - 手札がいっぱいで引けなかったときの揺れは、ネイティブ側で手札を 1 枚の絵として動かしていた。カードの絵が多いと、揺れのあと透明なまま残ることがある。揺れは JS 側で動かし、終わったら位置を 0 に戻す。

### 音量の設定（2026-10-07、オーナーの要望）

- タイトルの「設定」から、BGM と効果音を別々に 0〜100 で変える。冒険中も、図鑑ボタンの隣や戦闘の左上から開ける。
- **50 が標準**で、設定を足す前の音量（効果音は `SOUND_MASTER_VOLUME` 0.51 × 各音、BGM は曲ごとの `volume`）に全体の 2 倍（上の `OUTPUT_GAIN`）をかけた音量。0 で無音、100 でさらにその 2 倍。PC に取り込むとき、別々に作られた「全体 2 倍」と「設定」のブランチを合わせた（`levels.ts` の `outputVolume` が `OUTPUT_GAIN` もかける）。ただし再生の音量は 1 が上限（それを超えるとブラウザが例外を出す）。効果音どうし・曲どうしのバランスは変えない。
- 計算は `src/audio/levels.ts` の `outputVolume`。設定の保持は `src/audio/audioSettings.ts`（ブラウザでは `localStorage`。スマホアプリを完全に終了すると 50 に戻る。起動のあいだは残すには保存用パッケージが要る）。
- BGM はスライダーを動かすと、流れている曲がその場で変わる。効果音は指を離したときと ± ボタンで、カードを出す音を一度鳴らす。
