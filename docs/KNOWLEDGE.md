## 1. プロジェクトの目的

- **Slay the Spire 2 にインスパイアされたオリジナルのデッキ構築型ローグライクゲーム**を作る（2026-10-03 再定義）。
  - ~~デッキ構築型ローグライク向けの汎用デッキトラッカー＆ビルド管理アプリ~~（変更: 2026-10-03。オーナーより「プレイ記録・分析用のトラッカーは定義の間違い」）
- カード・キャラクター（エージェント）・敵はデータ定義を追加するだけで増やせる拡張性を重視。
- 進め方: まず戦闘 1 回を遊べるようにし、キャラクター固有の特性は決めずに無個性な初期デッキから始める。
- 将来構想: エリート・休憩所・ショップ・イベント・宝箱の中身、キャラクター固有カード、PHP/Laravel + AWS バックエンド連携（セーブ・ランキング等）、AI シナジー分析。
- **現在のフェーズ: フロントエンド（ローカルで遊べるプロトタイプ）に集中。** バックエンド連携やデータ永続化はまだ行わない。

### 参考にしているスレスパの戦闘仕様（2026-10-03 調査）

- 毎ターン開始時: エナジーを最大値（3）に戻し、5 枚ドロー。プレイヤーのブロックは 0 に戻る。
- カードはコスト分のエナジーを払って使い、使ったカードは捨て札へ。ターン終了時に手札は全て捨て札へ、余ったエナジーは失われる。
- 山札が尽きたら捨て札をシャッフルして山札にする。
- ブロックは攻撃ダメージを 1:1 で防ぐ。敵のブロックは敵自身のターン開始時に消える。
- 敵は次の行動をインテント（攻撃: 剣アイコン＋ダメージ、`6x3` は多段攻撃、防御: 盾アイコン、バフ・デバフ）で予告する。
- 基本カード: ストライク（1 コスト・6 ダメージ）、防御（1 コスト・ブロック 5）。スレスパ 2 の初期デッキは各 4〜5 枚＋キャラ固有カード。
- 未実装の主な要素: 敏捷、脱力（与ダメージ -25%）、弱体（被ダメージ +50%）、複数の敵。
- 実装済みの拡張効果（2026-10-03）: 多段攻撃、自己 HP 損失、筋力（戦闘中 / このターン）、ターン終了ブロック、廃棄、使用時コピー追加。
- 参考: [Combat Mechanics (StS2 Wiki)](https://slaythespire-2.com/guides/combat-mechanics-guide)、[Mechanics (StS1 wiki.gg)](https://slaythespire.wiki.gg/wiki/Mechanics)

### 開発スタイル

- 週末を使った個人開発。
- まず Expo のローカル UI/UX プロトタイプで小さく検証し、段階的に拡張する長期ロードマップ。

### 提案・設計の判断基準

- **プレイヤー体験を最優先する。** 機能や設計を提案するときは「プレイ中・プレイ後のプレイヤーにとって嬉しいか」を最初の判断軸にする。
  - 例: スマホの片手操作でカードを出しやすいこと、敵のインテントと自分の状態がひと目で分かること、1 戦の手応え。
- 週末開発なので、1 回の作業で完結して動くものが確認できる小さな単位で進める。

### Phase 1 の設計方針（フロントエンド）

- ドメインモデルは UI から独立したモジュール（例: `src/domain/`）に置き、Phase 2 の Laravel API のリソースと 1 対 1 で対応付けられる形にする。
- ロジック（枚数加算、統計計算など）は純粋関数として切り出し、テストしやすくする。
- 状態管理は Custom Hooks（例: `useDeck`, `useRelics`）に閉じ込め、後でローカル保存や API 呼び出しに差し替えられるようにする。

### 品質担保ルール（AI 活用開発）

- TDD の考え方をベースにする。ロジック変更時は型チェック（`npx tsc --noEmit`）を徹底する。

  - 要承認: パッケージの追加・削除、一括削除やプロジェクト外の操作、`git push` / `reset --hard` / `--force`、`sudo`、デプロイ・外部サービス操作。

### レリック・ポーション（2026-10-03）

- 「ラン開始時ですでに所持している」前提。`STANDARD_RUN` に最大 HP 70、レリック 4 個、ポーション 3 個を持たせている。
- 効果の型を `src/domain/effect.ts` の `Effect`（damage / block / gainEnergy / draw / heal）に共通化し、カード・レリック・ポーションで共用（旧 `CardEffect` は廃止）。damage は敵、それ以外はプレイヤーにかかる。
- レリック（`src/domain/relic.ts`）: `trigger`（combatStart / turnEnd / combatWon）と任意の `condition`（noBlock）で自動発動。
  - 錆びた錨 ⚓: 戦闘開始時ブロック 10 / 灯火のランタン 🏮: 戦闘開始時エナジー +1 / 不動の石 🪨: ターン終了時ブロック 0 ならブロック 6 / 闘志の血潮 🩸: 勝利時 HP 6 回復
- ポーション（`src/domain/potion.ts`）: 自分のターン中ならエナジー消費なしで使用、使うとスロットが空（null）になる。
  - 炎のポーション 🔥: 20 ダメージ / 鉄壁のポーション 🛡️: ブロック 12 / 俊敏のポーション 💨: 3 枚ドロー

- UI: `src/components/combat/items/`（`ItemBar` が画面上部に左レリック・右ポーションを並べ、タップで `ItemInfo` を表示）。レリックは発動時に金色に光って跳ねる。回復は緑のフラッシュと「+6」。

- ロジックの自動プレイで確認済み（開始時の錨・ランタン、ポーション 3 種、空きスロットの無視、不動の石の条件、勝利時の回復）。

### 戦闘エフェクト（2026-10-03）

- 追加パッケージなし。React Native 標準の `Animated` のみ使用（`react-native-reanimated` は未導入）。
- 仕組み: ロジックが `CombatState.events`（直前の操作 1 回分の `hit` / `blockGain` / `defeated`）を書き出し、UI がそれを読んで演出する。reducer が操作のたびに `clearEvents` で前回分を捨てる。
- 1 回の操作で複数イベントがあると `MOTION.eventStagger`（280ms）ずつずらして再生する（敵の多段攻撃が 1 発ずつ見える）。
- 演出の内容:
  - HP が減った: 揺れ（10 以上で大きく）、赤フラッシュ、赤いダメージ数値のポップ。プレイヤーが被弾したら画面全体の縁も赤く光る（`DamageVignette`）。
  - ブロックで防ぎきった: 拡大して戻るバウンド、青フラッシュ、「ガード！」。
  - ブロック獲得: バウンド、青フラッシュ、「+5 🛡️」。
  - 撃破: フェードアウトしながら縮む。勝敗画面は最後の演出が終わってからフェードイン。
  - HP バーは滑らかに減り、減った分を明るい残像が遅れて追いかける。
- ファイル: `src/components/combat/effects/`（`useCombatEvents` / `FighterEffects` / `FloatingText` / `DamageVignette`）。タイミングは `src/theme.ts` の `MOTION`。
- 効果音（2026-10-03）: `expo-audio` で再生。音源は `scripts/generate-sounds.mjs` で波形から合成した WAV（`npm run sounds` で `assets/sounds/` に再生成。権利問題なし）。
  - イベントと音の対応は純粋関数 `src/audio/combatSounds.ts` の `soundForEvent`。カード使用（`cardPlayed` イベント）・打撃・大ダメージ（10 以上）・ガード・ブロック獲得・被弾・勝利・敗北の 8 種。
  - 再生は `src/audio/soundPlayer.ts`（起動時に全音を先読み。失敗してもゲームは止めない）。`src/hooks/useCombatSounds.ts` が演出と同じ時間差で鳴らす。
  - ~~マナーモード中は鳴らさない（`playsInSilentMode: false`）~~（変更: 2026-10-03。Android 実機で音が出なかった。Android ではこの設定だとバイブモードでも消音される）→ `playsInSilentMode` は Android で true（メディア音量に従う）、iOS で false（消音スイッチに従う）。他アプリの音楽は止めない（`mixWithOthers`）。

  - `app.json` の expo-audio プラグインでマイク権限・録音権限・バックグラウンド再生を無効化（ネイティブビルド時のみ影響）。
- BGM（2026-10-04）: タイトル・通常戦闘・エリート戦・ボス戦・ショップの 5 曲（`src/audio/music.ts`）。音源は `scripts/generate-bgm.mjs`（`npm run bgm` で `assets/music/` に再生成、計約 9.9MB・22.05kHz モノラル WAV）。
  - 全曲がメインテーマ「三つの旗」の素材（導入の動機・A メロ・サビ・オルガンの駆け上がり、ニ短調）を共有する。オーナーは「メインテーマのコードやフレーズがどの曲にも入っている」構成が好き。
  - **オーナーの方針**: サビはタイトルと通常戦闘に入れず**エリート戦で初登場**。曲の出だしは曲ごとに変える（同じフレーズで始めない）。共通の旋律は曲の途中にあればよく、共通箇所は少なめに。長さはタイトル ≒ 通常 < エリート < ボス。
  - タイトル 72 BPM・40 秒（笛、サビなし）/ 通常 100 BPM・38 秒（ベルと笛、サビなし）/ エリート 156 BPM・43 秒（ギターとオルガンのリフ、溜めのあとサビ）/ ボス 176 BPM・60 秒（新しい前奏とリフ → ボス専用の旋律 → サビ → ホ短調へ上がる新しいサビ）/ ショップ「にぎわいの市場」128 BPM・52 秒（ニ長調、ハープ・笛・ボンゴ・シェイカー。商店街のにぎわい）。
  - 共通箇所: A メロの頭（タイトルは倍の長さ・通常は前半 4 小節・エリートは全部・ショップはニ長調にして手回しオルガン風）、サビ（エリート・ボス）。ボスには A メロを入れない。
  - 方針の相談（AI の意見）: ターン制で考える時間が長いので、通常戦闘は落ち着いた曲、ボスで激しい曲にすると山場が引き立つ。
  - 再生: `src/audio/musicPlayer.ts`（フェードイン 0.6 秒 / フェードアウト 0.9 秒）。各画面は `useMusic(id)`（`src/hooks/useMusic.ts`）で開いている間だけ流す。タイトル・ショップ・戦闘（敵の `rank` で `battleMusicFor`）。戦闘は決着したら `null` にして勝敗の効果音が聞こえるようフェードアウト。マップ・報酬などは無音。アプリがバックグラウンドに回ったら一時停止。
  - 図鑑の「🎵 BGM」タブで試聴できる（`MusicCatalog`）。試聴は `previewMusic` / `endPreview` で、図鑑を閉じると試聴前の曲（タイトル曲など）に戻る。
  - ループ再生。曲末の余韻は曲頭に回り込ませて合成しているので継ぎ目が目立たない。expo-audio にループ開始位置の指定が無いので、前奏も毎回流れる。
  - 合成の仕組み: `scripts/bgm-engine.mjs`（音名・楽器・打楽器・トラック・ミックス）、`scripts/bgm-song.mjs`（曲をコード記号・旋律・伴奏 / ベース / ドラムの型のデータで書き、`renderSong` で合成。旋律の拍数が小節数と合わないと書き出し時にエラー。転調・拡大・長調化の変換もここ）。`seedNoise` で曲ごとに乱数を初期化しているので、曲を足したり消したりしても他の曲の音は変わらない。音声モード設定は効果音と共通（`soundPlayer.ts` の `configureAudioMode`）。
  - 経緯: 最初の戦闘 3 曲（静寂の書庫 / 試練の回廊 / 決戦）→ オーナーの好きな 3 曲（テイルズ「剣を以って切り拓け」/ エターナルアルカディア「アルマダとの戦い」/ ポケモン SM「戦闘！島キング・島クイーン」）の雰囲気を参考にした試作 10 曲（旋律は流用しない）→ 3 曲の平均の試作 04「三つの旗」が好評 → 04 の変奏 10 曲 → 今の構成に決定。不採用の曲とその生成スクリプトは削除済み（git 履歴に残る）。
  - 容量が気になったら m4a などへの圧縮を検討（ffmpeg は未導入）。
- 既知の制限: HP バーと数値は操作の瞬間に最終値へ変わるため、多段攻撃では HP バーが先に減り、ポップだけが 1 発ずつ遅れて出る。

### キャラクターの 3D 化（2026-10-04）

- エージェントと全 18 体の敵を、ローポリの 3D（球・箱・円錐などの組み合わせ）で表示。`expo-gl` + `three` を直接使う。
  - ~~`@react-three/fiber`~~ は承認されたが見送り。ネイティブ版が `expo-asset` / `expo-file-system` も必要とするため、追加パッケージを最小にした。
- ファイル（`src/components/combat/model3d/`）:
  - `modelTypes.ts`: モデルの設計図の型（`ActorModel` / `ModelPart`）。three.js に依存しない純粋なデータ。
  - `modelBuilders.ts`: 型ごとの組み立て関数（人型・スライム・四つ足・翼・亡霊・ゴーレム・目・竜・砂時計・虚無の王）。色と装備（武器・兜・盾・マント）を変えて使い回す。
  - `actorModels.ts`: エージェント id / 敵 id → モデルの対応表。**ここに無いキャラクターは絵文字で表示**される（新しい敵を足したら、ここにも 1 行足すと 3D になる）。
  - `actorStage.ts`: 設計図から three.js のシーンを作って描画する。three.js はブラウザの `<canvas>` 前提なので、`expo-gl` のコンテキストに最低限の代用品を被せて渡している。
  - `ActorFigure.tsx`: `GLView` を置き、毎フレーム描画。初期化に失敗したら絵文字に切り替える。
- 動き: 待機中は呼吸・浮遊・伸び縮み（モデルごと）、翼のはばたき、輪の回転。自分の行動で相手の方へ体を傾け、被弾するとのけぞる。従来の踏み込み・エフェクト絵文字（`ActorMotion`）はそのまま外側で動く。
- 向き: モデルは「相手側が +x」で作り、敵は描画時に左右反転する。正面向き（人型など）と横向き（獣・竜）は `yaw` で角度を変えている。
- 大きさ・反応時間は `src/theme.ts` の `ACTOR_FIGURE`（描画領域 128）。
- 確認方法: 同じ描画コードをブラウザ（WebGL2）で動かして全モデルの見た目を確認済み。
- **実機で 2D のままだった問題（2026-10-04）**: expo-gl の WebGL2 コンテキストは `WebGLRenderingContext` を継承している（ネイティブ側の実装）ため、three.js（r163 以降）の「WebGL1 は非対応」チェックで例外になっていた。ブラウザでは起きない。`actorStage.ts` で `WebGLRenderer` 生成の間だけグローバルの `WebGLRenderingContext` を隠して回避。
  - 初期化・描画で失敗したときは `console.warn` で原因をターミナルに出し、絵文字表示に切り替える。

### ラン中の演出（強化・回復・マップ選択・画面切り替え）（2026-10-04）

- 仕組み: 各ロジック（休憩所・イベント・恩恵・章の移動…）には手を入れず、操作の前後のラン状態を比べて出来事を作る純粋関数 `diffRunEvents`（`src/logic/runEvents.ts`）。型は `src/domain/runEvent.ts` の `RunEvent`（`heal` / `upgrade` / `goldChange` / `cardGain`）。どこで回復・強化しても同じ演出になり、新しい入手経路を足しても演出側の変更は要らない。
  - 強化の検出: 強化前のカードが減り、その `upgradeCard` 後の id（`xxx+`）が同じ数だけ増えたら強化とみなす（`findUpgrades`）。

  - `useRun` の reducer は `runStoreReducer`（ラン本体 + 出来事の順番待ち）。`runReducer` 自体は変えていない。演出が終わったら `dismissEvent` で取り除く。
- 演出（`components/run/effects/`、`RunRoot` がどの画面の上にも 1 件ずつ重ねる）:
  - 強化（`UpgradeReveal`）: 槌が振り下ろされ → 金床の音と閃光 → 「強化前 → 強化後」を並べ、強化後のカードは弾んで金色に光り ✨ がきらめく。違いを読めるよう自動では閉じず、出きったらタップで閉じる。複数枚（イベントのランダム強化など）も並べて出す。
  - 回復（`HealBurst`）: 画面が緑に光り、回復量が弾んで出て、HP バーが伸び、✚ が立ちのぼる。最大 HP が増えたら併記。操作は止めない（タッチは下に通す）。章の移動の全回復でも出る。

### カードのイラスト（2026-10-04）

- 全 21 枚にイラスト。上から名前 → 絵（`CARD_ART.heightRatio` × 幅、種類の色の細枠）→ 種類 → 説明文。絵の右下に種類の紋章（アタック ⚔️ / スキル 🛡️ / パワー ✨、`CARD_TYPE_EMBLEM`）。全画面のカード（手札・報酬・ショップ・デッキ一覧・強化演出・入手演出）が `CardView` 1 つなので一括で反映。
  - 2026-10-04 修正: 最初は名前の帯を絵の下端に重ねていたが、「イラストが入っていないように見える」との指摘で、名前を絵の上に出して絵を隠さないようにし、画像も明るく補正、紋章を追加。`Image` は上下左右 0 の絶対配置ではなく `width/height: '100%'` で大きさを明示。
- 画像は AI 画像生成（4:3）。2026-10-04 に暗めの油彩調から、太い輪郭線のカラフルなカートゥーン調へ全面的に描き直し、同日さらにアニメ調ファンタジー RPG のカード絵（セル塗り・絵画的な背景・劇的な光）に描き直した。いずれもストライクの絵を参照画像にして絵柄をそろえ、HP を払うカードは血ではなく紅や紫のエネルギーで表現。生成元ファイル名は `jrpg-card-<id>` / `jrpg-bg-<map|combat>-<act>` で、`node scripts/resize-art.mjs <生成先> jrpg-` で取り込む。
- `scripts/resize-art.mjs <元画像フォルダ> [接頭辞]` で縮小: `<接頭辞>card-<id>` → `assets/cards/<id>.jpg`（320×240、品質 80、21 枚で約 490KB）、`<接頭辞>bg-<map|combat>-<章>` → `assets/backgrounds/`（720×1280、品質 82）。縮小には expo の依存に含まれる `jimp-compact` を使う（パッケージ追加なし。PIL / ImageMagick はこの環境に無い）。元画像（1024×768）はリポジトリに入れていない。

### 手札の上限 10 枚（2026-10-04）

- 手札は `MAX_HAND_SIZE`（10、`src/logic/combat.ts`）まで。`drawCards` が上限で止め、引けなかった分は山札に残る（上限で止まったときは捨て札のシャッフルもしない）。ターン開始のドロー・カード・ポーション・レリック、どの経路でも同じ。
- 引くカードは手札がいっぱいでも使える（コストは払う。使うと手札が 1 枚減るので、その分は引ける）。
- 引けなかったら `handFull` イベント（`blocked` = 引けなかった枚数）とログ「手札がいっぱいで N 枚引けなかった」。引いた枚数のログ「カードを N 枚引いた」も `drawCards` が実際の枚数で書く（ターン開始のドローにも出るようになった）。
- 演出（`components/combat/effects/HandFullEffect.tsx`、`Hand` が包む）: 手札が左右に揺れ、「手札がいっぱい！ N 枚引けなかった」の帯が弾んで出て消える。こもった「ブブッ」の効果音（`hand-full`）。上限に達している間は手札の右上に「10/10」を出す。
